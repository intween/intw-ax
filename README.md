# 제안요청서 AX 자동작성

제안요청서(RFP)와 회사가 승인한 자료를 바탕으로 요구사항을 추적하고, 근거가 확인되는 제안서 초안을 작성하도록 돕는 웹 도구입니다. 결과물은 담당자가 검토하고 승인한 뒤 사용합니다.

## 현재 상태

- 제품 기획 및 저장소 초기 설정 단계입니다.
- 이 저장소는 시작 시점에 비어 있었습니다. 실행 가능한 앱이나 개발 명령은 아직 없습니다.
- 원본 제안요청서, 회사 실적·인력 자료, 고객 문서는 저장소에 복사하지 않습니다.
- Supabase 프로젝트는 준비되어 있습니다. Vercel에는 `intw-ax` 프로젝트 쉘이 있지만 GitHub와 연결되지 않았고 아직 Production 배포가 없어 서비스 URL은 동작하지 않습니다.

## 사용자가 하게 될 일

1. 사업 공고와 제안요청서 파일을 프로젝트에 추가합니다.
2. 도구가 문서 구조, 표, 필수 조건, 배점, 일정, 제출 형식을 읽어 요구사항 목록으로 정리합니다.
3. 요구사항마다 승인된 회사 자료의 근거를 연결하고, 부족한 자료는 `확인 필요`로 표시합니다.
4. 초안을 편집하고 근거 위치와 변경 이력을 검토합니다.
5. 담당자가 승인한 결과만 DOCX/HWPX 등으로 내보냅니다.

## 제품 원칙

- 생성 문장에는 근거 파일과 페이지·문단 또는 승인된 회사 자료의 출처를 표시합니다.
- 실적, 인력, 수치, 인증, 수행 약속을 만들어 내지 않습니다. 근거가 없으면 확인 질문을 남깁니다.
- 제안요청서와 회사 자료를 외부 AI 서비스로 보내기 전에 공급자, 보존 정책, 비용, 개인정보 처리 범위를 확인합니다.
- 파일 형식과 크기를 검사하고, 원본 파일은 덮어쓰지 않습니다.
- 프로젝트별 파일과 접근 권한을 분리하고, 비밀정보와 실제 고객 자료를 테스트 데이터로 사용하지 않습니다.

## 기술 및 실행 방법

프런트엔드는 React와 JavaScript/JSX로 구현합니다. 화면은 React 컴포넌트로 구성하고 TypeScript (`.ts`, `.tsx`)는 사용하지 않습니다. Vercel framework가 필요한 경우 Next.js의 JavaScript 구조를 사용합니다.

앱 구조와 실행 명령은 저장소 현황 조사 후 결정합니다. 실행 가능한 개발 명령은 첫 애플리케이션 scaffold와 함께 이 섹션에 추가합니다. Supabase, Vercel, API 설정은 `PLAN.md`와 `.env.example`에 기록하며 실제 비밀값은 기록하지 않습니다.

## 저장소와 배포

- GitHub: [intween/intw-ax](https://github.com/intween/intw-ax) (소유자는 개인 계정 `intween`)
- Vercel 프로젝트: [intw-ax 대시보드](https://vercel.com/intween-temp/intw-ax), Hobby (`intween_temp` 팀)
- GitHub 앱 연결과 자동 배포는 저장소 소유자 `intween` 계정이 권한을 설정한 뒤 구성합니다.
- 현재 production deployment가 없어 서비스 URL은 아직 없습니다. 첫 배포가 완료되면 실제 URL을 여기에 추가합니다.

## 개발 참여
